# portifolio-tech

Este repositório documenta o desenvolvimento do portfólio interativo de Márcio dos Santos Gomes. Concebido como um meta-projeto, esta aplicação atua simultaneamente como o produto final e como um estudo de caso técnico, demonstrando a aplicação prática de engenharia de software de ponta a ponta.

## Visão Executiva e Objetivo
O propósito deste projeto é materializar a trajetória técnica e profissional do desenvolvedor, integrando a base acadêmica em Análise e Desenvolvimento de Sistemas e a especialização em Gestão de Projetos Ágeis. O desenvolvimento prioriza a qualidade estrutural, evidenciando o domínio sobre a concepção de produtos, desde o levantamento de requisitos até a entrega contínua (CI/CD) focada no ecossistema Frontend.

## Stack Tecnológico e Fundamentos
A aplicação é construída sobre um alicerce tecnológico moderno e práticas rigorosas de engenharia:
- Frontend: React, JavaScript, HTML, CSS.
- Padrões Arquiteturais: Clean Architecture, Clean Code, Princípios SOLID.
- Infraestrutura e DevOps: Integração e Entrega Contínuas (CI/CD), orquestração de deploy via Vercel.

## Engenharia de Interface e Design System
Para assegurar a escalabilidade e a consistência visual da aplicação, a interface é estruturada através de um Design System proprietário, planejado no Figma.
- Design Tokens: Centralização de variáveis estruturais, englobando paleta de cores corporativa, tipografia e escala padronizada de espaçamentos.
- Componentização: Desenvolvimento de componentes de interface isolados, orientados ao Princípio da Responsabilidade Única (SRP), mapeados rigorosamente do design para o código React.

## Governança Ágil e Gestão de Projetos
O ciclo de desenvolvimento obedece a metodologias ágeis, garantindo previsibilidade e rastreabilidade técnica. O gerenciamento ocorre integralmente via Kanban no GitHub Projects.

## Padrões de Versionamento
O repositório adota a especificação Conventional Commits para garantir um histórico semântico, automatizável e de fácil auditoria. A taxonomia adotada inclui:
- feat: Introdução de novas funcionalidades.
- fix: Resolução de anomalias ou falhas no código.
- chore: Manutenção de infraestrutura, atualizações de dependências e configurações.
- docs: Inserção ou alteração de documentação.
- refactor: Reestruturação de código sem alteração de comportamento funcional.

## Documentação Técnica
A rastreabilidade das decisões de engenharia é mantida junto ao código estrutural. Diretórios específicos neste repositório conterão:
- Architecture Decision Records (ADRs): Registro formal e justificativa para adoção de bibliotecas, frameworks e padrões arquiteturais.
- Pipeline de CI/CD: Documentação do fluxo automatizado de validação e deploy.
